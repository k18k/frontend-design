# Visual hierarchy

## Purpose

Visual hierarchy controls what people notice, group, and interpret before they read carefully. It is functional information architecture rendered visually.

## Primary levers

Use a limited set deliberately:

- scale,
- typographic weight/style,
- contrast,
- color,
- position,
- whitespace/proximity,
- alignment,
- repetition,
- enclosure,
- imagery,
- motion.

Adding more emphasis mechanisms does not create more hierarchy. If everything is emphasized, nothing is.

## Grouping before decoration

Try this order for grouping:

1. proximity,
2. alignment,
3. heading/label hierarchy,
4. subtle background/surface change,
5. border/divider,
6. container/card only when a bounded group is semantically useful.

This order is not absolute, but it prevents the common reflex of wrapping every section in a rounded box.

## Card test

A card is justified when the content is meaningfully one portable/selectable/bounded object or when the surface needs distinct grouping from its surroundings.

Remove a card when:

- it exists only to create padding,
- cards are nested repeatedly,
- every page section has identical enclosure,
- the border/shadow adds no grouping information,
- whitespace and headings would communicate the same structure more clearly.

## Scan path

A good screen can usually be skimmed as:

`where am I? -> what matters? -> what can I do? -> details if needed`

Inspect the interface at thumbnail size or with eyes unfocused. The major regions and dominant action should still be apparent.

## Balance and density

Balance is not symmetry. Give visual weight proportional to importance and content.

Density is contextual:

- expert monitoring/data work can support dense layouts,
- high-stakes or unfamiliar decisions often need more separation,
- marketing/editorial surfaces can use larger rhythm and expressive composition,
- mobile cannot simply inherit desktop density.

## Distinctiveness without novelty tax

To avoid generic output, derive visual character from the product:

- tone and audience,
- content type,
- brand attributes,
- typography,
- imagery/illustration strategy,
- composition,
- color relationships,
- shape language,
- motion behavior.

Do not intentionally sabotage usability merely to be “different.” Familiar interaction patterns can live inside a distinctive visual system.

## Common hierarchy failures

- five equally prominent buttons,
- title, metric, CTA, badge, and alert all competing for first glance,
- too many font sizes without semantic roles,
- identical styling for navigation, metadata, and actions,
- gray-on-gray “subtle” UI that removes meaningful contrast,
- excessive separators that fragment rather than group,
- decorative illustrations taking priority over task content,
- large hero treatment on routine internal workflows,
- repeated centered blocks that prevent scanning.
